This tutorial teaches you how to look up an existing Alias to retrieve its details (the Payment Credential). This process, known as resolution, is fundamental for initiating a payment.

## Requirements

Before attempting to retrieve an alias, ensure you have the following:
     - **API Access:** You have the base URL for the Ledger's API `/v2`
     - **Signer Setup:** You have an authenticated Signer identity with the required permissions to perform `GET` operations on Anchor records.
     - **Alias Key:** You know the specific Alias Key `:handle` you wish to look up (e.g., a phone number or email address).

     ### Interpret the Response

     The response body contains the resolved alias details, which include the Payment Credential necessary to execute a transaction.

     Key data points in the response include:
        - `handle`: The requested Alias Key.
        - `alias_type`: The type of identifier used (e.g., email, phone_number).
        - `account_data`: The detailed, private financial information (Payment Credentials).
        - `status`: The current state of the alias (must be `active` for use in new payments).

 ## Handling Third-Party Integration and Failures

 In environments integrated with a Centralized Directory (like DICE), the Ledger performs a local-first check. If the alias is not found in your local federated directory, the Ledger may forward the resolution request to the third-party system.

If the alias is not found or is in the Suspended or Cancelled state, the Ledger returns an error status (e.g., `404 Not Found` or a specific error code indicating the alias is inactive).
