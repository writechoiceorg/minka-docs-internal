A Domain is a container that segments data and operations into designated areas within the Minka Ledger.

Think of a Domain as a secure, virtual workspace. It builds boundaries that let you safely manage permissions, isolate data, and reduce risk in a large system.

<Callout type="warn">
If Domains are not used, all operations and data are considered global and flat. This means any participant or permission rule could potentially access or affect the entire system.
</Callout>

## Key Benefits

Domains provide two primary benefits:

### Data Isolation

Domains cleanly separate different parts of your system. This allows you to:

- Isolate data by organization, region, or function.
- Enforce targeted rules by applying different Policies and routes to distinct data subsets without affecting the global system.
- Prevent crossover, ensuring participants in one Domain cannot access data or operate in another.

### Risk Containment and Management

Domains are a powerful tool for managing security and permissions at scale.

    - **Manage Multi-Tenancy:** You can use Domains to manage different organizations (tenants) within the same ledger, limiting each to its own "workspace."
     - **Contain Permissions:** Risk is contained within the Domain. Even if you grant a user unlimited permissions, the system guarantees that user cannot view, modify, or perform actions outside that specific Domain.

## How Domains Work with Permissions

Domains are the top-level container for your authorization model. The system for granting permissions works like this:

1.  A Domain is created to define the secure boundary (e.g., "Organization-A").
2.  Policies, which are sets of rules (e.g., "can create wallets"), are attached to that Domain.
3.  Circles, which are groups of users (Signers), are also attached to the Domain and linked to those Policies.

This model ensures that a Signer in "Organization-A" can only perform actions defined by "Organization-A's" policies, and only on data within that same Domain.
