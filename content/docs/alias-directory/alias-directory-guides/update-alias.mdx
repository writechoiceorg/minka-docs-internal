In the Minka Ledger, an anchor's status determines its availability and operational validity. This allows you to manage an alias's lifecycle, such as temporarily disabling it for security reasons or reactivating it.

This operation is used to set the following statuses :

- ``ACTIVE``: The anchor is valid and available for use.
- ``SUSPENDED``: The anchor is temporarily disabled and cannot be used in new transactions.

All status changes are written to the ledger, ensuring traceability.

<Callout title="Third-Party Integration">
In regulated environments that require Third-Party Integration, the Ledger performs additional steps after receiving your signed request. This may include third-party validation and adding compliance-required Timestamps to the record before the update is finalized. You only need to submit the request, the Ledger handles the compliance workflow.
</Callout>

## Pre-requisites

Before you begin, ensure you have the following in place:

    - **API Access:** You have the base URL for the Anchors API `/v2`
    - **Signer Setup:** You have an authenticated Signer identity and the necessary private key for signing requests.
    - **Existing Alias Handle:** You must know the Alias Key of the Anchor record you intend to modify or delete.
    - **Authorization:** Your Signer must have the necessary permissions (defined by Policies and Circles) to execute `PUT` and `DEL` operations on Anchor records.

## Update Alias Status via SDK, API, and CLI

You can update an alias's status using the SDK, API, or CLI.

<Tabs items={['SDK', 'API', 'CLI']}> 
  <Tab value="SDK"> 
  Use the SDK to read the existing record, modify it in memory, and send the update.

      <Steps> 
        <Step>
        1. First, initialize the LedgerSdk with your server configuration and secure signer credentials.

        ```typescript
        async function createAnchor() {
        const sdk = new LedgerSdk({
            ledger: '<ledger-handle>',
            server: '<server-url>',
            timeout: 15000,
            verifyResponseProofs: true,
            signer: {
            format: 'ed25519-raw',
            public: '<signer-public-key>',
            },
            secure: {
            iss: '<signer-handle>',
            sub: 'signer:<signer-handle>',
            aud: '<ledger-handle>',
            exp: 60,
            keyPair: {
                format: 'ed25519-raw',
                public: '<signer-public-key>',
                secret: '<signer-private-key>',
            },
            },
        });

        const keyPair = {
            format: 'ed25519-raw',
            public: '<signer-public-key>',
            secret: '<signer-private-key>',
        };
        ```
        
        </Step> 
        
<Step>
2. Before you can update an anchor, you must first retrieve its current record.
    ```typescript
    const record = (await sdk.anchor.read('<alias-value>')).response.data;
    ```
</Step> 
        
        <Step>
       3. Use the `.from()` method to start with the existing record. You must preserve all existing data using `.data(record.data)` and set the new status in both the `.meta()` object and the `.sign()` method's `custom.status` field.

    <Callout>
        When updating the status, you must preserve 100% of the existing data within the anchor. The SDK's `.data(record.data)` method handles this for you.
    </Callout>

    ```typescript
      await sdk.anchor
        .from(record)
        .data( // Preserve all existing data
            {
                ...record.data
            }
        )
        .meta( { // Set the new status in the meta object
            status: "<status-value>", // e.g., "SUSPENDED"
            proofs: []
        }
        )
        .hash()
        .sign([{ // Sign with the new status
            keyPair,
            custom:{
                status: "<status-value>", // e.g., "SUSPENDED"
                moment:"2025-04-14T14:23:45.123Z" // ISO 8601 datetime
            }
        }])
        .send();
    }
    ```
        </Step> 
        
        <Step>
        4. Handle the response
        You receive `200 OK` and the updated anchor object. The "API" tab shows a diff example of this response. 
        </Step> 
      </Steps> 
  </Tab> 
  
  <Tab value="API"> 
  Send a `PUT` request to the `/v2/anchors/{handle}` endpoint to update the data.
  
    <Steps> 
      <Step>
      1. The request body must contain the full anchor object, including all existing data (which must be preserved). You must update the `meta.status` field to the new status. The signature in `meta.proofs` must also include a `custom.status` field set to the new status, a `custom.moment` field, and a `custom.reason` code.

      <Step>
      1a. Visual diff of changed fields

      The following diff highlights only the changed field in the request body:

      ```diff
      {
        "meta": {
          "status": "SUSPENDED",
          "proofs": [
            {
              "custom": {
                "status": "SUSPENDED",
                "moment": "2025-04-14T14:23:45.123Z"
              }
            }
          ]
        }
      }
      ```
      </Step>

      <Step>
      2. Send your signed request to `PUT /v2/anchors/{handle}`, replacing `{handle}` with the alias you are updating. 
      </Step>

      <Step>
      3. If successful, you receive `200 OK` and the updated anchor object. The response body reflects your changes.
      </Step>
    </Steps>
  <Callout>
  The PUT operation handles both data changes and status changes. You can use a single request to update non-critical custom data (like an owner's name) and the operational status simultaneously.
  </Callout>
  </Tab>

<Tab value="CLI"> 
The Minka CLI provides an interactive prompt to help you build the update payload. It automatically handles fetching the latest record, signing the new payload, and submitting the request.

  <Steps> 
    <Step>
    1. Run the `minka anchor update` command, specifying the alias you want to change:
        
        ```bash
        minka anchor update <alias-handle>
        # Example: minka anchor update example@email.com
        ```
    </Step>
    <Step>
      2. The CLI will prompt you to select which fields you want to update (e.g., `custom_data`, `status`).
    </Step>
    <Step>
    3. Confirm the changes and provide your Signer credentials when prompted.
    </Step>
  </Steps>
</Tab>
</Tabs>
