This tutorial teaches you how to look up an existing Alias to retrieve its details, this process can be done via API or trough the Minka Ledger Studio.

## Retrieve an Alias via API

You can get the details of a specific alias using the `GET /v2/anchors/{handle}` endpoint.

### Pre-requisites

Before you start, ensure you have the following:

     - **API Access:** You have the base URL for the Ledger's API `/v2`
     - **Signer Setup:** You have an authenticated Signer identity with the required permissions to perform `GET` operations on Anchor records.
     - **Alias Key:** You know the specific Alias Key `{handle}` you wish to look up (e.g., a phone number or email address).

### Perform the Request

Follow these steps to successfully resolve an alias and retrieve the associated financial information:

1. To look up a specific alias, append the unique Alias Key to the endpoint path  `GET /v2/anchors/` using `GET /v2/anchors/{handle}`. If the alias key is user@example.com, the full URL would look like this:

        ```
        GET /v2/anchors/user@example.com
        ```

2. Send a `GET` request to the constructed URL. This request requires a signed payload in the body, but it does require authentication (e.g., a Bearer token) to ensure the request comes from an authorized party.

        ```json
        GET /api/v2/anchors/<alias-value> HTTP/1.1\r\n' +
            'Accept: application/json, text/plain, */*\r\n' +
            'X-Received: 2025-04-14T14:23:45.123Z\r\n' +
            'X-Dispatched: 2025-04-14T14:23:45.123Z\r\n' +
            'Authorization: Bearer <token>\r\n' +
            'X-Ledger: <ledger-handle>\r\n' +
            'User-Agent: LedgerSDK/2.21.0\r\n' +
            'Accept-Encoding: gzip, compress, deflate, br\r\n' +
            'Host: <ledger-host-url>\r\n' +
            'Connection: keep-alive\r\n' +
            '\r\n'
        ```

If the request is successful and an Active Anchor record matches the handle, the Ledger returns a `200 OK` status with the full Anchor details. See the example below:

The response body contains the resolved alias details, which include the payment credentials necessary to execute a transaction. The key parameters in the response include:
            - `handle`: The requested Alias Key.
            - `alias_type`: The type of identifier used (e.g., email, phone_number).
            - `account_data`: The detailed, private financial information (Payment Credentials).
            - `status`: The current state of the alias (must be `active` for use in new payments).


 ## Third-Party Integration

 In environments integrated with a Centralized Directory (like DICE), the Ledger performs a local-first check. If the alias is not found in your local federated directory, the Ledger may forward the resolution request to the third-party system.

If the alias is not found or is in the Suspended or Cancelled state, the Ledger returns an error status (e.g., `404 Not Found` or a specific error code indicating the alias is inactive).
