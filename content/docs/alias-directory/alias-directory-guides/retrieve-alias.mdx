This how-to guide teaches you how to look up an existing alias to retrieve its associated anchor record and financial details. This Alias Lookup is a foundational step for routing payments or verifying alias ownership. You can retrieve a single alias by its unique handle (e.g., a phone number or email) using the SDK, API or CLI.


<Callout title="Federated Lookup">
The lookup operation can be performed on your local federated directory. Depending on your system's configuration, if an alias is not found locally, the system may be set up to query an external or centralized directory
</Callout>

## Pre-requisites
Before you start, ensure you have the following:

     - **API Access:** You have the base URL for the Anchors API `/v2`
     - **Signer Setup:** You have an authenticated Signer identity with the required permissions to perform `GET` operations on Anchor records.
     - **Alias Key:** You know the specific Alias Key `{handle}` you wish to look up (e.g., a phone number or email address).

## Resolve Alias via SDK, API, and CLI

<Tabs items={["SDK", "API", "CLI"]}>
  <Tab value="SDK">
    Use the SDK to construct requests and handle authentication. Follow these steps:

1. First, initialize the ``LedgerSdk`` with your server configuration and secure signer credentials.

        ```typescript
        async function createAnchor() {
        const sdk = new LedgerSdk({
            ledger: '<ledger-handle>',
            server: '<server-url>',
            timeout: 15000,
            verifyResponseProofs: true,
            signer: {
            format: 'ed25519-raw',
            public: '<signer-public-key>',
            },
            secure: {
            iss: '<signer-handle>',
            sub: 'signer:<signer-handle>',
            aud: '<ledger-handle>',
            exp: 60,
            keyPair: {
                format: 'ed25519-raw',
                public: '<signer-public-key>',
                secret: '<signer-private-key>',
            },
            },
        });

        const keyPair = {
            format: 'ed25519-raw',
            public: '<signer-public-key>',
            secret: '<signer-private-key>',
        };
        ```

2. Use the ``anchor.read()`` method, passing the ``alias`` handle as the only parameter.

    ```typescript
    async function getAnchor() {
      const  anchor  = await sdk.anchor.read('<alias-value>').response.data;

      console.log(
        "Retrieved anchor details:",
        JSON.stringify(anchor, null, 4)
      );
    }
    ```
3. If successful, the method returns the full anchor object and the API returns a ``200 OK`` status.
  </Tab>
  <Tab value="API">
    Query the Ledger using the `GET /v2/anchors/{handle}` endpoint.
    
1. Construct the request replacing `{handle}` in the endpoint URL with the actual Alias you want to resolve.

            ```
            GET /v2/anchors/{handle}
            # Example: GET /v2/anchors/user@example.com
            ```

2. Send a `GET` request to the constructed URL. Although this is a GET request, it requires authentication (e.g., a Bearer token) to ensure the request originates from an authorized party. See the example below:

      ```json
      GET /api/v2/anchors/user@example.com HTTP/1.1
      Accept: application/json
      Authorization: Bearer <token>
      X-Ledger: <ledger-handle>
      Host: <ledger-host-url>
      ```

3. If successful and an ACTIVE Anchor record matches the handle, you receive `200 OK` with the full Anchor details.
 
 <Callout type='warning'> 
If the alias is not found or is in the `SUSPENDED` or `CANCELLED` state, the Ledger returns an error status (e.g., `404 Not Found` or a specific error code indicating the alias is inactive).
 </Callout> 
  </Tab>
  <Tab value="CLI">
    Use the Minka CLI `anchor show` command to resolve the alias. The CLI constructs the request and uses your configured Signer credentials for authentication.

            ```bash
            minka anchor show <alias-handle>
            # Example: minka anchor show carlos6@minka.io
            ```
  </Tab>
</Tabs>
