This how-to guide teaches you how to look up an existing Alias to retrieve its associated financial details, which is known as Alias Resolution. You can perform this process using either the Minka CLI or the Ledger API.

## Pre-requisites
Before you start, ensure you have the following:

     - **API Access:** You have the base URL for the Ledger's API `/v2`
     - **Signer Setup:** You have an authenticated Signer identity with the required permissions to perform `GET` operations on Anchor records.
     - **Alias Key:** You know the specific Alias Key `{handle}` you wish to look up (e.g., a phone number or email address).

## Resolve the Alias and Retrieve Details
Follow these steps to successfully resolve an alias and retrieve the associated financial information (the Payment Credential).

    ### Resolve using the Minka CLI
    Use the Minka CLI's `anchor show` command to quickly resolve the alias. The CLI constructs the request and uses your configured Signer credentials for authentication.

            ```bash
            minka anchor show <alias-handle>
            # Example: minka anchor show carlos6@minka.io
            ```
    ### Resolve using the API
    You can directly query the Ledger using the `GET /v2/anchors/{handle}` endpoint.
    
  1. **Construct the Request:** Replace `{handle}` in the endpoint URL with the actual Alias Key you want to resolve.

            ```
            GET /v2/anchors/{handle}
            # Example: GET /v2/anchors/user@example.com
            ```

  2. **Send the Request:** Send a `GET` request to the constructed URL. Although this is a GET request, it requires authentication (e.g., a Bearer token) to ensure the request originates from an authorized party. See the example below:

      ```json
      GET /api/v2/anchors/user@example.com HTTP/1.1
      Accept: application/json
      Authorization: Bearer <token>
      X-Ledger: <ledger-handle>
      Host: <ledger-host-url>
      ```

The response body contains the resolved alias details, which include the payment credentials necessary to execute a transaction. The key parameters in the response include:
            - `handle`: The requested Alias Key.
            - `alias_type`: The type of identifier used (e.g., email, phone_number).
            - `account_data`: The detailed, private financial information (Payment Credentials).
            - `status`: The current state of the alias (must be `active` for use in new payments).


  ## Third-Party Integration
 In environments integrated with a Centralized Directory (like DICE), the Ledger performs a local-first check. If the alias is not found in your local federated directory, the Ledger may forward the resolution request to the third-party system.

If the alias is not found or is in the `SUSPENDED` or `CANCELLED` state, the Ledger returns an error status (e.g., `404 Not Found` or a specific error code indicating the alias is inactive).
