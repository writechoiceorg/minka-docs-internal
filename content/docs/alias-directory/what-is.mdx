---
title: What is the Alias Directory
---

The Alias Directory enables you to simplify payment initiation by linking complex financial data to simple, human-readable identifiers. It is the core component for Real-Time Payment (RTP) environments where users expect to initiate transfers using an email, phone number, or national ID number instead of a bank account number. It is composed of the following:

- **Alias Key:** The simple, user-friendly identifier used for lookups.
- **Payment Credentials:** The complex, private financial information required to execute a payment (e.g., account number).
- **Anchor:** The auditable ledger record that securely links the Alias Key to the Payment Credential.

With the Alias Directory you can manage the entire lifecycle of these linkages, ensuring that payment recipients can be reliably and securely resolved.

## Architectural Models

The Alias Directory can operate in different ways depending on the ecosystem's needs:

- **Federated Directory:** Each participating financial institution (or group) manages its own local set of aliases for its customers. 
- **Centralized Directory:** To ensure an alias is unique across the entire financial ecosystem and to allow payments between customers of different institutions, the Federated Directory often integrates with a third-party Centralized Directory.

Read more about these models in the [Federated and Centralized Alias Directories](/docs/alias-directory/fed-cen-dir) page.

## Working with Aliases

The Alias Directory allows you to perform the following:

- **Register and Link Aliases:** You register a new payment recipient by creating an Anchor record. This action links a simple Alias Key to the recipient's secure Payment Credentials.
- **Look Up Account Information:** The primary function of the Directory is to resolve an alias. When you need to send a payment, you look up the recipient using their Alias Key to retrieve the necessary Payment Credential before confirming the transaction with the user.
- **Manage the Alias Lifecycle:** You maintain data integrity and compliance by managing the status and information associated with each Anchor record throughout its life.
