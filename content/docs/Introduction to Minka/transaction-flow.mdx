This page explains how a transaction moves through the Minka platform, from its initiation by a user to its final settlement in a ledger. Understanding this flow helps you see how Minka's packaged solutions (Channels, Rails, Gateway, and Ledger) work together to create a complete payment network.

The flow generally follows four stages:
- **Origination:** A user initiates the payment (e.g., via QR code or alias) using Minka Channels.
- **Network Processing:** The transaction is sent to a network operator (like an ACH or Central Bank) that uses Minka Rails to manage the core network.
- **Intermediary Routing:** A participant bank or institution uses Minka Gateway to receive the transaction from the network and route it to the correct destination.
- **Final Settlement:** The transaction is recorded in the destination's Minka Ledger, which acts as the ultimate system of record.

## Roles 
The product flow highlights two distinct roles for institutions within the ecosystem: Provider and Participant.

### Provider
A Provider is responsible for the core network infrastructure, such as a central bank or ACH operator. Their responsibilities include:
    - Ensuring the network can communicate with any centralized systems.
    - Connecting to local channels.
    - Testing and processing both credits and debits.

### Participant
A Participant is a member of the network, such as a bank, that connects to the provider's infrastructure. Their role is to:
    - Test connections to channels.
    - Processing debits received from the network. 

## Tools and Components
While the diagram shows the high-level flow between packaged products, several underlying tools are required to make this flow functional. These include:
    - **Bridges:** Most Minka Ledgers are not standalone. They use Bridges to connect to other services, such as legacy bank cores or external centralized directories.
    - **Security:** A universal transaction flow requires security protocols to be in place. This is handled by Ledger components like Circles and Policies, which define permissions and access rules.
    - **CLI/SDK:** You use tools like the Minka CLI or SDKs to build, test, and integrate with this transaction flow.
