title: Intents
---

An Intent represents a user's desire or idea to perform an action.

When a user initiates an operation, they create an intent. When this operation is sent to the system, the sender is not immediately sure if the action will occur; they will only see the outcome later once the intent has been processed. 

For a client wishing to make a transaction, creating an intent is the necessary step, often achieved via a single API call.

The ability to create an intent is central to the End-to-End Transaction Flow and Payment Initiation processes.

## Intents and Claims

The concept of Intent is closely linked to Claims, which provide the specific details of the actions being requested.

- An Intent represents the purpose behind an action.

- An intent includes several statements, called Claims, that describe the actions the user wants to perform.

The relationship between intents and claims is key to keeping financial operations reliable.

Claims allow operations to be grouped together to ensure atomicity, meaning that they will either all succeed or all fail together. This prevents partial or incomplete operations in the system.

## Application

Claims are used in scenarios where multiple actions must be finalized together:

- Taxes: If a payment requires collecting a tax, multiple claims might be used. The system ensures that if the payment goes through, the taxes must also be paid; otherwise, the entire payment cannot be completed, preventing a partial operation.

- Exchanges: For currency exchange (e.g., giving $100 and receiving €80), placing both parts into two claims ensures that the exchange is atomic, meaning the user is guaranteed to receive the euros if they provide the dollars.
