---
title: What is the Alias Directory
---

The Alias Directory enables you to simplify payment initiation by linking complex financial data to simple, human-readable identifiers. It is the core component for Real-Time Payment (RTP) environments where users expect to initiate transfers using an email, phone number, or national ID number instead of a bank account number.

You use the Alias Directory to manage the entire lifecycle of these linkages, ensuring that payment recipients can be reliably and securely resolved.

## Components

The Alias Directory relies on three pre-existing concepts working together:

- **Alias Key:** The simple, user-friendly identifier used for lookups.
- **Payment Credentials:** The complex, private financial information required to execute a payment (e.g., account number).
- **Anchor:** The auditable ledger record that securely links the Alias Key to the Payment Credential.

## Primary Functions

The Alias Directory allows you to perform three main operations that support the entire payment lifecycle.

1. **Register and Link Aliases:** You register a new payment recipient by creating an Anchor record. This action links a simple Alias Key to the recipient's secure Payment Credentials.

    <Callout>
    You initiate this process with the following endpoint: `POST /v2/anchors`
    </Callout>

2. **Look Up Account Information (Resolution):** The primary function of the Directory is to resolve an alias. When you need to send a payment, you look up the recipient using their Alias Key to retrieve the necessary Payment Credential before confirming the transaction with the user.

    <Callout>
    You initiate this retrieval with the following endpoint: `GET /v2/anchors/handle`
    </Callout>

3. **Manage the Alias Lifecycle:** You maintain data integrity and compliance by managing the status and information associated with each Anchor record throughout its life.
    - **Update Status:** Suspend or reactivate an alias for operational or compliance reasons with the endpoint: `PUT /v2/anchor/handle`
    - **Update Custom Data:** Change non-critical custom information associated with the alias, such as the owner's name, using the following endpoint: `PUT /v2/anchor/handle`
    - **Cancel Alias:** Permanently deactivate and remove the alias linkage from the directory with the following endpoint: `PUT /v2/anchor/handle`
