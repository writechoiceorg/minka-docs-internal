The Alias Directory is a service that provides a simple, secure method for resolving payment recipients by linking a user-friendly identifier to the necessary financial details.

It acts as a layer over the Ledger's Anchor records to simplify payment initiation.

## Components

The Alias Directory relies on three pre-existing concepts working together:

- **Alias Key:** A simple, public identifier (e.g., phone number or email address) used to initiate the lookup.
- **Payment Credentials:** The private financial information (e.g., account details) required to execute the transaction.
- **Anchor:** The single Ledger record used to register and link a specific Key to its Credentials.

## Purpose

The Alias Directory simplifies the payment flow for participants by focusing on two key actions:

- **Registering User Keys:** Provides a mechanism for customers to register their payment information to a simple key via an Anchor record.

- **Payments Resolution:** Allows participants to look up the necessary payment information based on the Alias Key before confirming the transaction with the end user.

## Workflow

The Alias Directory relies on a two-step workflow that separates information retrieval from payment execution, ensuring security and maximum flexibility:

<Steps>
<Step>
### Lookup and Resolution
1. The participant's application calls the Alias Directory endpoint using a known Alias Key. 

2. The Directory resolves the request by querying its Anchor records and returns the associated Payment Credential.
</Step>
<Step>
### Confirmation & Payment Execution
3.  The retrieved Payment Credential is shown to the end-user for confirmation.

4. Upon user confirmation, the bank sends a separate request using the retrieved credential.
</Step>
</Steps>

<Callout>
  The payment can then be executed either within the Minka Ledger or through any external payment system (e.g., a banking core or third-party network). 
</Callout>
