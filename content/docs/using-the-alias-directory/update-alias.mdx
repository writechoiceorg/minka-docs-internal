In the Minka Ledger, an anchor's status determines its availability and operational validity. This allows you to manage an alias's lifecycle, such as temporarily disabling it for security reasons or reactivating it.

This operation is used to set the following statuses:

- `ACTIVE`: The anchor is valid and available for use.
- `SUSPENDED`: The anchor is temporarily disabled and cannot be used in new transactions.

All status changes are written to the ledger, ensuring traceability.

<Callout title="Third-Party Integration">
In regulated environments that require Third-Party Integration, the Ledger performs additional steps after receiving your signed request. This may include third-party validation and adding compliance-required Timestamps to the record before the Ledger finalizes the update. You only need to submit the request, the Ledger handles the compliance workflow.
</Callout>

## Prerequisites

Before you begin, ensure you have the following in place:

- **[SDK Initialization](/docs/Quickstart/sdk-initialization):** The Minka SDK must be initialized and configured. See the Quickstart section for setup instructions.
- **API Access:** You have the base URL for the Anchors API `/v2`
- **Signer Setup:** You have an authenticated Signer (a cryptographic key pair that represents your identity and authorizes operations on the ledger) identity and the necessary private key for signing requests.
- **Existing Alias Handle:** You must know the Alias Key (the handle, or alias identifier) of the Anchor record you intend to modify.
- **Authorization:** Your Signer must have the necessary permissions (defined by Policies and Circles) to execute `PUT` operations on Anchor records.

## Update Alias Status via SDK, API, and CLI

You can update an alias's status using the SDK, API, or CLI.

<Tabs items={["SDK", "API", "CLI"]}>
  <Tab value="SDK">
    Use the SDK to update alias status from your backend services. The SDK handles authentication, request construction, and response parsing.

    1. Before you can update an anchor, you must first retrieve its current record using `sdk.anchor.read()`.

    2. Use the `.from()` method to start with the existing record and set the new status in both the `.meta()` object and the `.sign()` method's `custom.status` field.

    <Callout>
    When updating the status, you must preserve 100% of the existing data within the anchor. The SDK's `.data(record.data)` method handles this automatically.
    </Callout>

    ```typescript
    import sdk from './ledgerClient'; // Your initialized SDK instance
    import { keyPair } from './config'; // Your key pair from SDK configuration

    async function updateAnchor(aliasHandle: string, newStatus: string) {
        try {
            // Step 1: Retrieve the current record
            const readResponse = await sdk.anchor.read(aliasHandle);
            const record = readResponse.data;

            // Step 2: Update the status
            const response = await sdk.anchor
                .from(record)
                .data({
                    ...record.data
                })
                .meta({
                    status: newStatus, // e.g., "SUSPENDED"
                    proofs: []
                })
                .hash()
                .sign([{
                    keyPair,
                    custom: {
                        status: newStatus,
                        moment: new Date().toISOString()
                    }
                }])
                .send();

            console.log('Alias updated successfully:', response.data);
            console.log('Status:', response.status); // Expected: 200
            return response.data;
        } catch (error) {
            console.error('Error updating alias:', error.message);
            // Handle specific error cases:
            // - 404: Alias not found
            // - 400: Invalid status or data format
            // - 401: Authentication failed
            throw error;
        }
    }

    // Execute the function
    updateAnchor('tel:+15551234567', 'SUSPENDED');
    ```

    3. On success, you receive `200 OK` and the updated anchor object.
  </Tab>

  <Tab value="API">
    Send a `PUT` request to `/v2/anchors/{handle}` to update the anchor status.

    1. Construct the request body with the full anchor object, preserving all existing data. Update `meta.status` to the new status. The signature in `meta.proofs` must include `custom.status` (set to the new status), `custom.moment`, and optionally `custom.reason`.

    <Callout>
    The `luid` (Ledger Unique Identifier) and `parent` fields are returned by the ledger when you retrieve the record. Include them in your update request to maintain record integrity.
    </Callout>

    ```json
    {
      "hash": "5831f42bd15da1cafa5a4a4623a398389a734766ad169fb4f3b6bdf80418712f",
      "luid": "$anc.-0847869HxNkGI2-Z",
      "data": {
        "handle": "<alias-value>",
        "wallet": "<wallet-id>",
        "target": "<target-account>",
        "symbol": "usd",
        "custom": {
          "name": "<name>",
          "idType": "<id-type>",
          "idNumber": "<id-number>",
          "entityType": "individual",
          "lastUpdated": "2025-04-02T05:10:30.822Z",
          "status": "verified"
        },
        "access": [
          {
            "action": "any",
            "signer": {
              "public": "gef6OID0o7ZFGTXutV62mh+zv5kgkFP3QLiR+N7syck="
            }
          },
          {
            "action": "read",
            "bearer": {
              "$signer": {
                "$record": "owner"
              }
            }
          }
        ],
        "parent": "6fbba0181fc0177365b62541ed7e94d8532ca6dd40651f23387d4c17d00967ec"
      },
      "meta": {
        "status": "SUSPENDED",
        "proofs": [
          {
            "method": "ed25519-v2",
            "public": "gef6OID0o7ZFGTXutV62mh+zv5kgkFP3QLiR+N7syck=",
            "digest": "482d687c0719d02eff65be40cafb9fbfb35a850fdc95e82c90765791ea6c52b8",
            "result": "HSx4A9sj1DwwiX71pjEI5eyJGvBpV8ViBF9dCLM4nmLfK8exRB4AA47lQe1w4QrdronMUBRq+rMSYx+yzTqrCw==",
            "custom": {
              "moment": "2025-04-14T14:23:45.123Z",
              "status": "SUSPENDED",
              "reason": "SECURITY_AUDIT"
            }
          }
        ]
      }
    }
    ```

    2. Review the visual diff. The following example highlights only the changed fields:

    ```diff
    {
      "meta": {
        "status": "SUSPENDED",
        "proofs": [
          {
            "custom": {
              "status": "SUSPENDED",
              "moment": "2025-04-14T14:23:45.123Z",
              "reason": "SECURITY_AUDIT"
            }
          }
        ]
      }
    }
    ```

    3. Send your signed request to `PUT /v2/anchors/{handle}`, replacing `{handle}` with the alias you are updating.

    4. On success, you receive `200 OK` and the updated anchor object.

    <Callout>
    The PUT operation handles both data changes and status changes. You can use a single request to update non-critical custom data (like an owner's name) and the operational status simultaneously.
    </Callout>
  </Tab>

  <Tab value="CLI">
    Use the Minka CLI to update alias status. The CLI handles request construction and signing.

    1. Run the `minka anchor update` command, specifying the alias you want to change:

    ```bash
    minka anchor update <alias-handle>
    # Example: minka anchor update example@email.com
    ```

    2. The CLI prompts you to select which fields you want to update (e.g., `custom_data`, `status`).

    3. Confirm the changes and provide your Signer credentials when prompted.
  </Tab>
</Tabs>
