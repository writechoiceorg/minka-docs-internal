In the Minka Ledger, an anchor's status determines its availability and operational validity. This allows you to manage an alias's lifecycle, such as temporarily disabling it for security reasons or reactivating it.

This operation is used to set the following statuses :

- ``ACTIVE``: The anchor is valid and available for use.
- ``SUSPENDED``: The anchor is temporarily disabled and cannot be used in new transactions.

All status changes are written to the ledger, ensuring traceability.

<Callout title="Third-Party Integration">
In regulated environments that require Third-Party Integration, the Ledger performs additional steps after receiving your signed request. This may include third-party validation and adding compliance-required Timestamps to the record before the Ledger finalizes the update. You only need to submit the request, the Ledger handles the compliance workflow.
</Callout>

## Prerequisites

Before you begin, ensure you have the following in place:

    - **SDK, CLI, or API Initialization:** Your chosen tool (SDK, CLI, or API proxy) must be initialized and configured. See [SDK, CLI, and API Initialization](/docs/Quickstart/sdk-cli-api-initialization) for setup instructions.
    - **API Access:** You have the base URL for the Anchors API `/v2`
    - **Signer Setup:** You have an authenticated **Signer** (a cryptographic key pair that represents your identity and authorizes operations on the ledger) identity and the necessary private key for signing requests.
    - **Existing Alias Handle:** You must know the Alias Key (the **handle**, or alias identifier) of the Anchor record you intend to modify or delete.
    - **Authorization:** Your Signer must have the necessary permissions (defined by Policies and Circles) to execute `PUT` and `DEL` operations on Anchor records.

## Update Alias Status via SDK, API, and CLI

You can update an alias's status using the SDK, API, or CLI.

<Tabs items={['SDK', 'API', 'CLI']}> 
  <Tab value="SDK"> 
  Use the SDK to read the existing record, modify it in memory, and send the update.

      <Steps> 
        <Step>
        1. Before you can update an anchor, you must first retrieve its current record using `sdk.anchor.read()`.
        </Step> 
        
        <Step>
        2. Use the `.from()` method to start with the existing record. You must preserve all existing data using `.data(record.data)` and set the new status in both the `.meta()` object and the `.sign()` method's `custom.status` field.

    <Callout>
        When updating the status, you must preserve 100% of the existing data within the anchor. The SDK's `.data(record.data)` method handles this for you.
    </Callout>

    ```typescript
    import sdk from './ledgerClient'; // Your initialized SDK instance
    import { keyPair } from './config'; // Your key pair from SDK configuration

    async function updateAnchor(aliasHandle: string, newStatus: string) {
        try {
            // Step 1: Retrieve the current record
            const readResponse = await sdk.anchor.read(aliasHandle);
            const record = readResponse.response.data;

            // Step 2: Update the status while preserving all existing data
            const response = await sdk.anchor
                .from(record)
                .data({
                    // Preserve all existing data
                    ...record.data
                })
                .meta({
                    // Set the new status in the meta object
                    status: newStatus, // e.g., "SUSPENDED"
                    proofs: []
                })
                .hash()
                .sign([{
                    // Sign with the new status
                    keyPair, // From your SDK configuration
                    custom: {
                        status: newStatus, // e.g., "SUSPENDED"
                        moment: new Date().toISOString() // Current ISO 8601 datetime
                    }
                }])
                .send();

            console.log('Alias updated successfully:', response.data);
            console.log('Status:', response.status); // Expected: 200
            return response.data;
        } catch (error) {
            console.error('Error updating alias:', error.message);
            // Handle specific error cases:
            // - 404: Alias not found
            // - 400: Invalid status or data format
            // - 401: Authentication failed
            throw error;
        }
    }

    // Execute the function
    updateAnchor('<alias-value>', '<status-value>'); // e.g., "tel:+15551234567", "SUSPENDED"
    ```
        </Step> 
        
        <Step>
        3. Handle the response
        You receive `200 OK` and the updated anchor object. The "API" tab shows a diff example of this response. 
        </Step> 
      </Steps> 
  </Tab> 
  
  <Tab value="API"> 
  Send a `PUT` request to the `/v2/anchors/{handle}` endpoint to update the data.
  
    <Steps> 
      <Step>
      1. The request body must contain the full anchor object, including all existing data (which must be preserved). You must update the `meta.status` field to the new status.       <Step>
      2. Send your signed request to `PUT /v2/anchors/{handle}`, replacing `{handle}` with the alias you are updating. 
      </Step>

      <Step>
      3. If successful, you receive `200 OK` and the updated anchor object. The response body reflects your changes.
      </Step>
    </Steps>
  <Callout>
  The PUT operation handles both data changes and status changes. You can use a single request to update non-critical custom data (like an owner's name) and the operational status simultaneously.
  </Callout>
  </Tab>

<Tab value="CLI"> 
The Minka CLI provides an interactive prompt to help you build the update payload. It automatically handles fetching the latest record, signing the new payload, and submitting the request.

  <Steps> 
    <Step>
    1. Run the `minka anchor update` command, specifying the alias you want to change:
        
        ```bash
        minka anchor update <alias-handle>
        # Example: minka anchor update example@email.com
        ```
    </Step>
    <Step>
      2. The CLI will prompt you to select which fields you want to update (e.g., `custom_data`, `status`).
    </Step>
    <Step>
    3. Confirm the changes and provide your Signer credentials when prompted.
    </Step>
  </Steps>
</Tab>
</Tabs>
