In Minka, creating an alias means registering a special type of **anchor** (a foundational ledger record that securely links an alias to a financial account) on the ledger. This anchor acts as the foundational record that connects a human-readable alias (like a phone number or email) to a specific **target** (the financial account where payments to this alias will be routed) account.

This operation is the first step in enabling an alias to be used for secure, real-time payments.

This guide provides three methods for creating an alias:

- Via SDK (Recommended): The simplest method, which handles complex tasks like hashing and signing.
- Via API: For direct integration with the REST endpoint.
- Via CLI: For command-line operations, scripting, and automation.

## Prerequisites

Before you start, ensure you have the following resources:

- **SDK, CLI, or API Initialization:** Your chosen tool (SDK, CLI, or API proxy) must be initialized and configured. See [SDK, CLI, and API Initialization](/docs/Quickstart/sdk-cli-api-initialization) for setup instructions.
- **API Access:** You have the base URL for the Anchors API (`/v2`).
- **Signer Setup:** You have an authenticated **Signer** (a cryptographic key pair that represents your identity and authorizes operations on the ledger) identity and the required private key with permissions to perform creation (`POST`) operations on Anchor records.
- **Required Data:** You have the specific Alias Key, the Wallet ID, and the Payment Credential details you intend to link.

    <Callout>
    In regulated environments (e.g., Centralized Directory like DICE), the Ledger performs additional steps, including third-party validation and adding compliance-required Timestamps to the record before completion.
    </Callout>

## Create an Alias via SDK, API, and CLI

<Tabs items={["SDK", "API", "CLI"]}>
  <Tab value="SDK">
This is the recommended method as the Minka SDK simplifies the process by handling object creation, hashing, and cryptographic signing. To do so follow steps below:

1. Construct the ``anchorData`` object using the required attributes.

        ```typescript
        const anchorData = {
            handle: "<alias-value>", // e.g., "tel:+15551234567"
            target: "<target-account>", // e.g., "svgs:12345@mybank.io"
            custom: {
                aliasType: "<alias-type-standard-value>",
                documentType: "<document-type-standard-value>",
                documentNumber: "<document-number>",
                accountType: "<account-type-standard-value>",
                accountNumber: "<account-number>",
                firstName: "<firstname>",
                lastName: "<lastname>",
                entityType: "individual", // Or "business"
            },
            access: [
                { action: "any", signer: { $record: "owner" } }
            ],
            schema: "person" // Or "business"
        };
        ```

2. Sign and Send the Request using the SDK's builder methods. The SDK handles the cryptographic operations.

    ```typescript
    import sdk from './ledgerClient'; // Your initialized SDK instance
    import { keyPair } from './config'; // Your key pair from SDK configuration

    async function createAnchor() {
        try {
            const response = await sdk.anchor
                .init()
                .data(anchorData)
                .meta({
                    labels: ["nidn:<document-number>"], // e.g., "nidn:0801198607268"
                    proofs: []
                })
                .hash()
                .sign([{
                    keyPair, // From your SDK configuration
                    custom: {
                        status: "ACTIVE"
                    }
                }])
                .send();

            console.log('Alias created successfully:', response.data);
            console.log('Status:', response.status); // Expected: 201
            return response.data;
        } catch (error) {
            console.error('Error creating alias:', error.message);
            // Handle specific error cases:
            // - 400: Invalid data format
            // - 409: Alias already exists
            // - 401: Authentication failed
            throw error;
        }
    }

    // Execute the function
    createAnchor();
    ```
3. On success, you receive the newly created anchor object and a ``201 Created`` status.
  </Tab>

  <Tab value="API">
    Construct the entire JSON payload, including cryptographic proofs, and submit it to the ``POST /v2/anchors`` endpoint.

1. Create a JSON object containing the ``hash``, ``data``, and ``meta`` fields. The data ``object`` contains the core alias information , and the ``meta`` object contains the proofs and labels.

        ```json
        {
        "hash":"5d40248a0f9e9f6be3e6d43dd3062ddf98e9187ea1c8eeedb151f4ba208c96e1",
        "data":{
            "handle":"<alias-value>",
            "wallet":"<standard bridge wallet>",
            "target":"<target-account>",
            "symbol":"<symbol>",
            "custom":{
                "aliasType":"<alias-type-standard-value>",
                "documentType":"<document-type-standard-value>",
                "documentNumber":"<document-number>",
                "accountType":"<account-type-standard-value>",
                "accountNumber":"<account-number>",
                "firstName":"<firstname>",
                "lastName":"<lastname>",
                "entityType":"<entity-type-standard-value>"
            },
            "access":[
                {
                    "action":"<action>",
                    "signer":{
                    "$record":"<circle>"
                    }
                }
            ],
            "schema":"person"
        },
        "meta":{
            "proofs":[
                {
                    "method":"ed25519-v2",
                    "public":"<public-key>",
                    "digest":"<digest-value>",
                    "result":"<result-value>",
                    "custom":{
                    "moment":"<request-sent-date>",
                    "status":"CREATED"
                }
                }
            ],
            "labels":[
                "nidn:<document-number>"
            ]
        }
        }
        ```

2. Send the complete JSON payload in a `POST` request to the ``/v2/anchors`` endpoint, including your authorization token in the headers.

3. On success, you receive `201 Created` and the full anchor object.
  </Tab>

  <Tab value="CLI">
    Use the Minka CLI to create Anchor records from your terminal. This method is useful for scripting and automation. Prepare a JSON file with the Anchor data and pass it to the CLI `create` command.

        1. Create a JSON file (e.g., `new-alias.json`) that contains the data for the new Anchor. The structure is similar to the `data` object used in the API method.
           
    ```json
        {
        "handle": "<alias-value>",
        "target": "<target-account>",
        "custom": {
            "aliasType": "PHONE",
            "documentType": "NIDN",
            "documentNumber": "<document-number>",
            "accountType": "<account-type-standard-value>",
            "accountNumber": "<account-number>",
            "firstName": "<firstname>",
            "lastName": "<lastname>",
            "entityType": "individual"
        },
        "access": [
            { "action": "any", "signer": { "$record": "owner" } }
        ],
        "schema": "person"
        }
        ```

        2. Use the Minka CLI `anchor create` command to submit the new record. The CLI handles the hashing and signing using your configured Signer credentials.
        
        ```bash
        minka anchor create \
        --file new-alias.json \
        --signer <your-signer-handle> \
        --label "nidn:<document-number>" \
        --status "ACTIVE"
        ```

        3. If successful, you see the newly created Anchor object in JSON, confirming registration on the Ledger.
  </Tab>
</Tabs>
