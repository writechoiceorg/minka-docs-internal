---
title: Alias Lifecycle Management
---

The status of an Alias (which is stored as an Anchor record in the Ledger) determines whether it can be used for payment resolution. You manage the lifecycle of an alias by changing its state, ensuring that the directory accurately reflects the availability and validity of the linked account information.

## The Alias States

1. Active

An Anchor in the Active state is fully functional and available for resolution. This is the default state upon successful creation of the Anchor via endpoint `POST /v2/anchors`.
    - **Functionality:** The alias is discoverable by other participants in the network and can be used to successfully retrieve the associated Payment Credential for payment initiation.
    - **Transition:** An alias in the Suspended state can be transitioned back to the Active state using the update operation.

2. Suspended

An Anchor in the Suspended allows you to temporarily deactivate an alias without permanently deleting the underlying record. The alias is flagged as inactive due to operational, legal, or customer service requirements.
    - **Functionality:** The alias is not resolvable for new payment lookups. However, the full history and data of the Anchor record remain intact in the Ledger.
    - **Transition:** You change an alias to the Suspended state (or back to Active) by sending an update request to the Anchor record, modifying its status field using the endpoint `PUT /v2/anchor/:handle`

3. Cancelled

The Cancelled state permanently removes the alias linkage from the directory. The record has been permanently deactivated. This is typically used when a user explicitly closes the associated account or requests the alias be removed permanently.
    - **Functionality:** The alias is no longer resolvable, and you cannot reactivate the record. If the user wishes to use the same Alias Key later, they must create an entirely new Anchor record.
    - **Transition:** You cancel an Anchor record using the endpoint `DEL /v2/anchor/:handle`

    <Callout>
    Even when an Anchor is Cancelled, the Ledger's core data integrity model ensures that the history of its creation and cancellation remains immutable and fully auditable.
    </Callout>
